# M6 · 通用设置（快捷键 / 导入导出 / 上下班提醒 / 背景图）

需求原文：`m03460`——「增加设置中可以一键显示浮窗的快捷键,可以导入、导出待办，代办导出为markdown格式和CSV格式，导入待办支持markdown和csv格式文件，增加上下班提醒，设置上午、下午的上下班时间来做提醒，距离下班还有多久，可以设置主窗口和浮窗的背景图片」。

设置面板从「只有推送渠道」变成两个页签：**推送渠道** / **通用**。文里的路径都能直接打开（`F:/develop/Ringtone/...`）。

## 二、上下班提醒为什么要做成「隐藏任务」

四个时间点（上午上班、上午下班、下午上班、下午下班）不是新的推送通道，而是往 `tasks` 里插 4 条 `hidden = 1` 的普通任务：

- 每条都是 `daily` 重复 + `remind_offsets`（提前 N 分钟时是 `[-N*60, 0]`，否则 `[0]`）；
- `tasks_on_day` / `task_stats` / `next_reminder` 都加了 `WHERE hidden = 0`，所以列表、计数、顶部「下一条提醒」都看不到它们；
- 但 `db::ensure_occurrences()` **故意没过过滤**：实例照常生成，于是幂等（`dedupe_key` UNIQUE）、失败退避（5s/30s/2min）、降级、配额、关机不补发这些语义**一行都不用重写**，全部白继承。

改设置走 `work::materialize()`：**先删光隐藏任务再重建**，每条建完立刻 `db::reset_occurrences_for_task()` 重建实例 —— 少这一步就会「改完下班时间今天不响、重启才好」。

## 四、本轮挖出的三个真缺陷（都已修）

1. **单位错**：`humanSpan()` 收的是**秒**，而我给它传了毫秒 → 主界面显示「距离下班还有 **64667 分 37 秒**」。修法：两处调用方 `/ 1000`，并在 `day.ts` 的函数注释里写明「参数是秒不是毫秒，库里 `*_ms` 先除以 1000」。
2. **同窗口改浓度不生效**：`localStorage` 的 `storage` 事件**只在别的文档**触发，所以拖动「主窗口浓度」时，浮窗会变、主窗口自己不变（要重启才变）。修法：`pingPhoto()` 额外 `dispatchEvent` 一个本窗口自定义事件，`watchPhoto()` 同时订阅它。
3. **界面上的 `**` 星号**：提示文案里写了 Markdown 的 `**重点**`，但那是纯文本，界面上原样显示星号。改成「」。

## 五、设计取舍

- **导入只新增不覆盖**：重复导入同一份文件不会翻倍（同一天 + 同标题跳过），也不会误删现有待办。
- **CSV 带 BOM、Markdown 不带**：CSV 要给 Excel 看（不带 BOM 打开是乱码）；Markdown 给人看，重复规则/提前提醒在导出里是 ` · ↻ 每天`、` · 提前 5 分钟`，两者**导入时都能认回来**（导出写全 `interval`/`until`，认不出就不猜）。
- **`csv_field` 把换行换成空格**：否则导入侧要处理跨行字段，收益不值那些代码。
- **过去的时间点不补发**：今天已经过掉的上下班点不会在启用瞬间连发四条（和「关机错过不补发」同一条规矩）。
- **图片复制进应用目录**：原图删掉、U 盘拔掉都不影响。
- **浓度是背景图自己的透明度**，不是窗口透明度：调低更淡（字更清楚），和「窗口透明度」是两件事。
- **快捷键必须带修饰键**：否则用户一敲字母就被全局抢走，正常打字全废。

## 六、已知缺口

1. 隐藏任务在界面上**完全看不到**（故意的）：要核对有没有真的排期，得看日志或 `send_log`；没有单独的「上下班提醒」筛选。
2. ~~**不认节假日**：每天都会响，周末也不例外~~ **已修**：上下班提醒现在用「工作日」规则（法定节假日不响、调休补班的周六日照响）。
3. ~~导入**不解析** Markdown 里的重复规则/提前提醒~~ **已修**：Markdown 也带重复规则与提前提醒，导入时能认回来（见 CHANGELOG 的「节假日感知 + 导入导出增强」）。
4. 浓度范围 10%~100%，不能再淡。
5. 图片不限大小：大图会以 data URL 进内存，建议 1MB 以内。
6. 快捷键只支持一把；冲突时只提示、不会自动换一个。
7. 导入失败明细最多列 20 条。
8. 上下班实例一次排到 7 天窗口内（每任务 14~16 条），改设置会整体重建（只动还没触发的实例，已发/已勾的记录不动）。
