# M6 · 交互与观感第二批（右键菜单 / 鼠标侧键 / 浮窗按钮 / 拖动顺滑 / 多屏 / 重点与配色）

对应六条需求：优化右键菜单、快捷键支持鼠标侧键、右上角加显示·隐藏浮窗按钮、浮窗拖动不流畅、
多显示器下浮窗边缘在两块屏之间变动、外观进一步优化（重点突出某些任务 + 多任务配色可区分但不乱）。

## 功能表

| 功能 | 怎么用 | 实现要点 |
| --- | --- | --- |
| 右键菜单（任务行） | 任务行上右键 | 四项：标记 / 取消重点、编辑（重复规则 / 提醒）、标记 / 取消完成、删除（红字）。菜单项按任务当前状态动态生成 |
| 右键菜单（浮窗条目） | 浮窗某一条上右键 | 三项：标记 / 取消完成、标记 / 取消重点、「打开主窗口」（分隔线之后） |
| 鼠标侧键叫浮窗 | 设置 → 通用 → 「鼠标侧键」选「侧键 4 / 侧键 5」 | 自写 Windows 低级鼠标钩子（`WH_MOUSE_LL`），**全局生效**、按下即弹浮窗，并且吞掉这次按键（不会再触发浏览器前进 / 后退） |
| 标题栏显示 / 隐藏浮窗 | 标题栏那个小方块图标（置顶按钮左边） | 走 `float_visible` / `toggle_float`；按钮亮起表示浮窗已显示 |
| 浮窗拖动 | 按住浮窗卡片拖到另一条边 | 手动 pointer 拖动（按下即停掉滑动动画、`setPointerCapture`、同一时刻只允许一次「读光标 + 摆窗口」），松手吸附并记住边与高度 |
| 多屏落点 | 把主窗口或浮窗放到另一块屏 | 浮窗贴边位置按**浮窗自己所在那块屏**的缩放算，不再跟着主窗口那块屏 |
| 重点（星标） | 右键 → 标记重点，或点任务行右侧的星标按钮 | 新字段 `tasks.star`（v6 迁移）；加粗标题 + 色条变粗，**不参与排序、不影响提醒** |
| 任务配色 | 默认开启，设置 → 外观 → 「任务配色」可关 | 8 色低饱和色板按任务 id 固定分配，只画成行首 3px 细条（完成的不画）；时间颜色表示紧急度：过期深红、30 分钟内红、再加一个小圆点 |
| 同窗口外观同步 | 改字号 / 字体 / 透明度 | `appearance.ts` 除了 `storage` 事件还派发本地事件（`storage` 只在别的窗口触发，同窗口收不到） |

## 三个真 bug（都不是猜的，是量出来的）

1. **右键菜单整宽跑到列表下面、看不见**（最严重的一个）
   - 现象：`.ctx-menu` 在 DOM 里、`rect` 也在，但截图里没有；`getComputedStyle` 报 `position: relative; z-index: 1; width: 460px`。
   - 根因：`styles.css` 里早就有 `.app > :not(.backdrop) { position: relative; z-index: 1 }`（给面板用的）。
     `:not()` 会把参数里的选择器算进优先级，所以这条是**两个类**，比单个 `.ctx-menu` 更高；菜单被它按成普通块级元素，
     又被 `.app` 的 `overflow: hidden` 裁掉。
   - 修法：选择器写成 `.ctx-menu.ctx-menu`（同权重靠后覆盖）。用 CDP `CSS.getMatchedStylesForNode` 确认过是谁赢的。
2. **任务行色条只有 3×4 像素**
   - 根因：我把那条细条的类名写成 `.bar`，而 hero 的「今日进度」进度条早就占了 `.bar`，还带 `height: 4px`；
     `top: 9px; bottom: 9px` 遇到显式高度就失效。
   - 修法：改名 `.tbar`（注释里写明别再用 `.bar`）。修完量到 `3×30`，`position: absolute` 生效。
3. **设置里出现字面的 `**` 星号**：新增的鼠标侧键提示写了 `**全局**`（界面是纯文本，不解析 Markdown）→ 改成「」。

环境坑（不是代码问题，但浪费了时间）：vite dev 会把某个模块**服务成空文件**——`src/styles.css` 一度只有 451 字节，
`src/icons.tsx` 也犯过（报 `does not provide an export named ...`），表现是整页没样式 / 白屏。`touch` 一下那个文件即好，
别急着重启 vite。

## 多屏落点：改前 / 改后（同一台机器，两块屏）

| 浮窗所在屏 | 屏参数 | 改前算落点用的 | 改后 `float_dock()` |
| --- | --- | --- | --- |
| `\\.\DISPLAY20` | 2560×1600 @150%，x=0 | 主窗口那块屏的 402 | `win_w=402, collapsed_x=2546, expanded_x=2158`（贴右）/ `-388 / 0`（贴左） |
| `\\.\DISPLAY5` | 1920×1080 @100%，x=−1920 | 仍按主窗口的 402 算 → 贴边位置偏差一百多像素 | `win_w=268, mon_left=-1920, mon_right=0, collapsed_x=-9, expanded_x=-268` |

同一份 `float_set_side` 调用，浮窗在哪块屏就用哪块屏的缩放与边界（`dock_monitor`：先按浮窗自身位置取 `monitor_from_point`，
取不到再退回主窗口所在屏 → 主屏）。改前 `268` 物理像素会被当成 `402`，正好在两屏交界处来回跳。

## 取舍（有意的）

- **鼠标侧键自己写钩子**而不是用现成插件：`tauri-plugin-global-shortcut` 底层的 `global-hotkey` 只认键盘，
  系统也没有「把鼠标键注册成全局热键」的接口。代价：安全软件可能对低级钩子敏感；所以默认关，装不上只警告、不挡启动。
- **菜单自绘**（不用系统原生菜单）：待办行与浮窗条目的菜单项要按状态动态变（是不是重点、是不是重复任务），
  原生菜单改文案要绕一大圈，而且浮窗是无边框小窗，原生菜单在上面表现不一致。
- **颜色只当标记，不当底色**：整行着色在 5 条以上就很乱；色条 + 时间颜色两层，能区分但不吵。
- **重点与紧急分开**：重点是你自己标的（星标），紧急是时间算出来的（过期 / 30 分钟内），两者叠加但互不替代。
- **星标不进排序**：`tasks.star` 只管显眼，排序仍按时间；`update` 的 SQL 故意不碰 `star`，编辑任务不会把星标弄丢。
- **拖动改成手动跟手**：原来的 `onMoved` + 400ms 去抖是「松手才吸附」，看起来一顿一顿；现在按下即停动画、指针移动直接摆窗口。

## 已知缺口

1. 浮窗只能贴左右两条边，不能拖到上下。
2. 拖动「跟不跟手」只能弱验证：CDP 合成的 pointer 事件不会移动真实系统光标，而代码读的是真实光标坐标
   （`cursor_position` 权限已确认可用、无异常），手感要人自己拖一下。
3. 右键菜单没有键盘导航（方向键 / Enter），只能鼠标点。
4. 鼠标侧键钩子是全局吞键：选上之后那块侧键在任何程序里都不再是「前进 / 后退」。
5. 多屏只处理了「缩放不同」这一种坑；显示器热插拔时若浮窗正在屏外，需要手动点一次显示浮窗。
6. 星标没有批量操作（不能一次给多条打重点）。
7. 颜色按任务 id 分配，删掉任务后新建的任务可能拿到相近的颜色（8 色循环）。
