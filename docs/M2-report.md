## 顺手抓到并修掉的 3 个真 bug

1. **改时间到过去，会弹一条过期提醒。**
   单测直接抓到的：把任务时间改到过去后，重建逻辑先扫了过期、后生成实例，新生成的又变回「待发」。
   已改成「删未来 → 重新生成 → **最后**扫过期」。（影响：你只改个标题就可能被弹一条早过期的提醒。）

2. **空跑的 tick 会白白撑大数据库自增 id。**
   每 5 秒都对已存在的提醒点重插一次，被 `INSERT OR IGNORE` 挡掉了数据、但**自增 id 照样往前跑**——
   实测 40 秒里 `occurrences.id` 从 1 涨到 14。现在先查已有提醒点，只插缺的那些（同类问题在长时间开机后会很明显）。

3. **新建一个「到期时刻已经过去」的任务会立刻弹通知，而同样情况走「编辑」却不弹。**
   两条路径行为不一致。现在统一：新建/编辑都会把已过期的提醒点直接标 `missed`，都不弹。

## 两个环境发现（不影响功能，但你该知道）

1. **你这台机器现在是锁屏状态**：Windows 把通知横幅压掉了，通知只进了「操作中心」。
   我核对了 Windows 自己的通知数据库（`wpndatabase.db`），两条通知的到达时间与我们的发送时间**毫秒级吻合**（12:03:25.113 / 12:04:25.185），
   所以是「系统收到了、只是没弹横幅」，不是没发出去。所以这次没能给你一张通知弹窗的截图——**解锁状态下才会看到横幅**。
2. **现在通知的「发送者」显示成 Windows PowerShell**：未打包运行的开发版会回退到系统自带的 AUMID。
   M5 做安装包 / 设置 AppUserModelID 之后，才会显示成 Ringtone。
