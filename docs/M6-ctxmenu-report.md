# M6 · 空白处右键菜单（留白 / 日期 / 浮窗）交付报告

目标：右键不再只有「任务行」和「浮窗条目」。**留白处、日期上、浮窗空白处**都能右键出菜单，把最常用的
几个动作（添加任务 / 设置 / 总览 / 开关浮窗 / 收进托盘）放到手边，并且能**从剪贴板一键新建**任务。

## 一、功能表

| 在哪右键 | 菜单项 |
| --- | --- |
| 主界面留白（列表空的地方、底部留白） | 添加任务 · 从剪贴板新建任务 · —— · 显示 / 隐藏浮窗 · 设置（推送渠道 · 通用）· 总览（这个月）· —— · 收进托盘（到点照样提醒） |
| 周条日期格 | 在 `10-09` 添加任务 · 跳到 `10-09`（就是当前看的那天时不出现）· 从剪贴板新建任务 |
| 月总览日期格 | 同上 |
| 浮窗空白处（卡片上、条目以外） | 添加任务（打开主窗口写）· 从剪贴板新建任务 · 打开主窗口 · 设置（打开主窗口） |
| 任务行（上一批做的） | 标记 / 取消重点 · 编辑（重复规则 / 提醒）· 标记 / 取消完成 · 删除 |
| 浮窗条目（上一批做的） | 标记 / 取消完成 · 标记 / 取消重点 · 打开主窗口 |

「从剪贴板新建任务」走的是**快捷录入**那套解析（`parseQuick`）：剪贴板里放 `明天九点交周报`，右键就能变成
明天 09:00 的任务；只取**第一行非空文字**，落在别的日子时主窗口会自己切过去。

## 二、取舍（为什么这么做）

1. **不留「退出」**。空白处误点代价太大（退出 = 到点不再提醒），退出继续留在托盘菜单里。
2. **浮窗只放四项**。浮窗窗口只有 268×236，菜单项多了会被窗口切掉（实测四项 `h = 143 < 236`）。
   所以浮窗里没有「总览」，都从「打开主窗口」绕。
3. **空白菜单的触发要能分清「哪里是空白」**。`onBlankCtx` 里先看 `e.target.closest("button, input, select, textarea, a, .task, .day, .md, .float-item, .ctx-menu")`，命中就**直接放行**——
   否则任务行 / 日期格子上会同时弹两个菜单（子元素的 handler 已经 `stopPropagation` 了，这里是第二道保险）。
4. **跨窗口动作走 `localStorage` 广播**（`sync.ts` 的 `pingFocusComposer` / `pingOpenSettings`），没上 Tauri `emit`：
   两个窗口同源，`storage` 事件够用，不用多一份事件白名单。浮窗点「添加任务」= `showMain()` + 广播，
   主窗口收到后先 `backToList()` 再开输入框并聚焦。
5. **「收进托盘」走 Rust 命令 `hide_main`，不用前端 `getCurrentWindow().hide()`**：前端 `hide()` 不经过
   `sync_float`，主窗口藏了浮窗却不顶上（和标题栏 ✕ 的行为不一致）；`hide_main` = `hide()` + `sync_float()`。
6. **日期菜单里「跳到这天」只在不是当前浏览日时才出现**，避免菜单里出现一个点了没反应的项。

## 三、实测证据（CDP 走真实界面，不是单测）

| 场景 | 结果 |
| --- | --- |
| 主界面留白右键 | 菜单 6 项文案与顺序全对；几何 `position: fixed; z-index: 60; 174×223`，窗口 460×720，没被 `.app` 的 `overflow: hidden` 裁 |
| 留白 →「添加任务」 | 输入框打开，placeholder = 「要做什么？（可写「明天九点交周报」）」 |
| 周条格子（10-08）右键 | `["在 10-08 添加任务","跳到 10-08","从剪贴板新建任务"]`；点「跳到」→ 列表切到 10-08 |
| 月总览格子右键 | `["在 10-10 添加任务","从剪贴板新建任务"]`（当天不出现「跳到」）；点「在 X 添加任务」→ 总览关闭、列表切到那天、输入框打开、聚焦 |
| 浮窗空白右键 | 四项；几何 `174×143`，浮窗窗口 268×236，没被切 |
| 浮窗 →「添加任务（打开主窗口写）」 | 主窗口 `is_visible = true` 且输入框打开 |
| 浮窗 →「设置（打开主窗口）」 | 主窗口从列表切到「设置」面板 |
| 留白 →「显示浮窗 / 隐藏浮窗」 | `float_visible` false → true → false，**菜单文案当场跟着变** |
| 留白 →「收进托盘」 | 主窗口 `is_visible = false`，**浮窗顶上**（修完 `hide_main` 之后）；之后 `show_main` → 主窗口回来、浮窗自己收起 |

## 四、修掉的三个真 bug

1. **「收进托盘」不弹浮窗**：菜单项原来调前端的 `getCurrentWindow().hide()`，绕过了 `sync_float`。
   改成 Rust 的 `hide_main`（`hide()` + `sync_float()`），和标题栏 ✕ 走同一条路。
2. **总览里点「在 X 添加任务」不回列表**：总览 / 设置都是**全屏 early-return 分支**，不先回列表的话输入框
   开了也看不见。抽出 `backToList()`，`openComposer()` 和 `pasteNewTask()` 都先调它。
3. **浮窗拖动一按就断（`setPointerCapture` 抛空）**：`dragStart` 是 `async`，里面 `await` 过之后 React 已经把
   合成事件的 `currentTarget` 置成 `null`，`e.currentTarget.setPointerCapture(...)` 抛
   `Cannot read properties of null (reading 'setPointerCapture')`（vite 日志里的 `Unhandled rejection`），
   拖动因此拿不到指针捕获——鼠标一滑出窗口就断。改成先存下元素与 `pointerId`，捕获失败时顺手把按下状态放掉。

## 六、已知缺口

1. 剪贴板读取用的是 `navigator.clipboard.readText()`，**在 CDP 里读不到**（`Document is not focused`，
   合成焦点不算）。真实用户右键时窗口是聚焦的，预期可用；如果真机上不行，兜底是加
   `tauri-plugin-clipboard-manager`（多一个依赖 + 权限）。
2. 菜单没有键盘导航（上下键 / 回车），只能用鼠标点。
3. 浮窗里的菜单只能四项（窗口尺寸限制），「总览」这类入口要经主窗口。
4. 留白菜单不区分「哪块留白」——列表底部留白和「今天还没有安排」的空白是同一个菜单。
5. 日期菜单没有「删除这天所有任务」这类批量动作（刻意不做，误删代价太大）。
6. 剪贴板新建走的是快捷录入的解析规则，识别不了的写法（如「下下周三」）会落到今天或报错，不会问你要日期。
7. 浮动菜单的定位是「出现在鼠标点的地方」并由窗口边界夹住，靠近右下角时会被推向中间（可接受，但不是原生行为）。
