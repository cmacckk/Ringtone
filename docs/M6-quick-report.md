# M6 · 快捷录入（一句话里认出日期 / 时刻 / 重复）

一句话总结：添加框里直接写「明天九点交周报」，不用再点时间、点重复；**但绝不猜**——认不出来就当普通标题。

## 认哪些说法

| 类别 | 支持的写法 | 例子 → 结果 |
| --- | --- | --- |
| 相对日 | 今天 / 明天 / 后天 / 大后天 / N 天后 | `明天九点交周报` → 2026-10-09 09:00，标题「交周报」 |
| 星期 | 周三 / 星期三 / 礼拜三，可带「本·这·下」 | `下周三下午两点例会` → 2026-10-21 14:00 |
| 月日 | `3月5日` `3月5号` `15号` | `10月20号交表` → 2026-10-20；今年的已过就顺延到明年 |
| 时刻 | `9点` `九点` `9点半` `9点20分` `9:20` `20:30` | `下午3:30开会` → 15:30 |
| 上下午 | 凌晨 / 早上 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 今晚 / 夜里 | `晚上八点` → 20:00；`中午12点` → 12:00 |
| 重复 | 每天 / 每日 / 每隔 3 天 / 工作日 / 每周一三五 / 每周二、四 / 每月8号 / 每年3月5日 | `每天九点喝水` → 每天 09:00 |

多个信息可以同时出现，会被拆开分别落到日期、时刻、重复三处。

## 三条设计原则

1. **只认确定的说法**。认不出就当普通标题——`下午` 后面没跟数字就不动（猜不出是几点）；
   `25点` `9点70分` 这种非法时刻也整体当标题，不做「修正」。
2. **先给用户看，再落库**。输入框下面实时显示 `识别到：明天 09:00 · 标题「交周报」`，
   认出来的片段会从标题里摘掉，摘成空的话退回原文（不能存出一条没有标题的任务）。
3. **时间已过去要提醒**。`识别到：今天 09:00 … · 时间已过去，不会提醒`——
   后端把已到点的实例记成「错过」，不会补发，所以这句话得在添加前说清楚。

## 代码

- `src/quick.ts`（新建）：纯函数
  `parseQuick(text, today, baseDay = today, nowMs = Date.now()) → { title, day, hm, repeat, label, past }`。
  不碰 React、时间从参数进来，所以能单独验证。
- `src/App.tsx`：添加框实时预览（`const quick = parseQuick(title, today, day)`）；
  `onAdd` 用解析结果落库（`date = parsed.day ?? 正在看的那天`、`时刻 = parsed.hm ?? 手填的`、
  `重复 = parsed.repeat ?? 手选的`）；**认出来的日期和正在看的那天不一样就自动跳过去**，
  否则用户会觉得「加了但没看见」。
- `scripts/shot.mjs`：`--eval` 加了 `awaitPromise: true`，这样才能用一条 `--eval` 跑多步异步操作。

## 首测抓到的 2 个真 bug

1. **「每周二、四」只认出周二**。周选择的正则只吃连写的星期字，`每周二、四` 里的顿号让它停在「二」，
   于是 `byday=[2]`、标题还剩下一个孤零零的「四」。
   修法：捕获组允许 `、,，和` 与空格做分隔，并且把映射不到数字的字符过滤掉（顿号会映射成 `undefined`）。
2. **跨年日期只显示 `03-05`**，看不出是哪年。修法：加 `dayText(day, today)`，同年才缩写成 `MM-DD`，
   跨年给完整日期（`2027-03-05 10:00`）。

## 我自己写错的 3 条期望值（值得记）

- `20:30 跑步`、`晚上八点` 在 17:20 输入 → 我把期望写成了「已过去」，实际是 `past=false`。**实际行为才是对的**。
- 「时间已过去」的基准是**正在看的那天**，不是今天：视图已经跳到 10-09 之后再输入「九点」，
  09:00 在 10-09 还没到，所以不该提示。第一版我把这个也算成 bug。
- 结论：**断言失败先确认期望值本身对不对**——这次 4 条失败里 3 条是测试写错，只有 1 条是真 bug。

## 已知缺口

- 不认：`半小时后`、`下周`（不带星期几）、`每两周`、`每月最后一个工作日`、`10/20`（斜杠格式）、英文写法。
- **手填时间和文字里的时间冲突时，文字赢**（`parsed.hm ?? hm`）。提示行会显示实际用的是哪个，
  但对「先填 10:00 再打字写九点」的人是反直觉的。
- 界面上的时间/重复/提醒控件**不会被解析结果改写**（只显示提示行），免得跟手填的值打架；
  代价是「提示行说 09:00、时间框还空着」看着不一致——以提示行为准。
- 解析的验证脚本是一次性的，不在仓库里；前端仍然没有自动化测试框架。
- 工作日 = 周一到周五，不看节假日调休。
