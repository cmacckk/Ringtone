# M6 第 1 项报告 · 重复规则

> 目标：待办可以「每天 / 工作日 / 每周某几天 / 每月某日 / 每年某日」重复，可以「每隔 N 天/周/月/年」，
> 可以设结束日期；**勾选 = 完成本次，系列继续**；真的不想再重复了要有个「停止重复」。
>
> 结论：已实现并实机验证。`cargo fmt/check/clippy/test`（106 个单测）与 `tsc/vite build` 全绿。

## 一、语义（我实现的定义，以后别随手改）

| 场景 | 行为 |
| --- | --- |
| 频率 | `daily` / `weekdays`（周一至周五）/ `weekly` / `monthly` / `yearly` |
| 间隔 | `interval` 1–99，界面上是「每隔 N 天/周/月/年」 |
| 每周的哪几天 | `byday` 1=周一 … 7=周日；**只有每周能用**，留空 = 跟任务起始日同一个星期几 |
| 结束日期 | `until`，**含当天**；留空 = 一直重复 |
| 实例从哪来 | 每次 tick 为未来 7 天（调度 horizon）生成 `occurrences`，关掉再开能接上 |
| 勾选 | 把 `done_ms` 写在那一天的实例上 + 实例标 `skipped`（不发通知）；**系列继续** |
| 起始日那行的勾选 | 含义同样是「完成本次」（判断用 `repeat_rule` 有没有值，**不是**用 `repeated`） |
| 取消勾选 | 那天的实例还没到点 → 回到 `pending`（还会响）；已经过去了 → `missed`（不补发） |
| 停止重复 | `repeat_rule = NULL` + 撤掉未来实例；任务本身和勾过的记录都留着 |
| 普通任务 | `repeat_rule` 为空 → 走原来的 `set_task_done`（完成整个任务） |
| 展开出来那行的 `day` | **仍然是任务自己的起始日**，不是正在浏览的那天（否则编辑一次就把整个系列挪走） |

数据模型：`tasks.repeat_rule` 是 v1 就有的可空 TEXT 列（存 `{"freq","interval","byday","until"}` 的 JSON），
所以**没有为了重复规则加字段**；只在 v3 迁移里给 `occurrences` 加了 `done_ms INTEGER`。

## 三、四个真实缺陷（都是写完测试才暴露出来的）

1. **`parse_repeat` 只做 JSON 解析** → `{"freq":"每小时"}` 也能通过，`matches_day` 走到兜底分支静默返回 false（这条任务永远不响）。
   修法：解析后校验频率白名单（`REPEAT_FREQS`）。
2. **每周 + `byday` 为空** → 条件写成了「这一周里哪天都响」，「每周」变成「每天」。
   修法：`byday` 为空时用**起始日那天的星期几**。
3. **起始日那行的完成状态没按天结算** → 重复任务在自己那天勾完，界面看不出任何变化
   （列表行的 `done` 来自 `tasks.done`，只有展开行走了按天结算）。修法：`done_ms` 结算提前到查询开头，所有行都合并。
4. **展开行把 `day` 覆盖成浏览日** → 双击改个标题就会把整个系列挪到当前浏览的那天。
   修法：展开时保留任务起始日；前端保存编辑也用 `t.day` 回存。

## 四、有取舍的设计决定

- **不加 `occurrences.state = 'done'`，改用新列 `done_ms`**：`state` 上有 CHECK 约束，加一个值就得重建整张表；
  `done_ms` 一个字段同时表达「完成了」和「别发通知」，迁移只是 `ALTER TABLE ADD COLUMN`。
- **迁移改成清单驱动**：`MIGRATIONS: &[(版本号, SQL)]`，版本号写在清单里、由 `migrate` 逐条比对执行；
  跑完还会自检「库里的版本 == `SCHEMA_VERSION`」，不一致直接报错。
  之前那种手写 `if current < 3` 的写法，加版本号时漏写一步就会留下「程序以为是新版、表结构还是旧的」的库。
- **展开窗口 = 7 天**：不会一次生成几年的实例把库撑大；每次 tick 续排，所以关机几天再开也能接上。
- **文案与线格式分家**：`describeRepeat()` 放 `src/day.ts`（格式化唯一出处），`parseRepeat()` / `repeatToJson()` 放 `src/api.ts`（线格式）。

测试写法上的一个教训：**别拿「今天」做状态断言**。本机真实时钟是 2026-10-08 16:5x，今天 09:00 早已过去，
`create_with_occurrences` 之后的重建会把过期实例扫成 `missed`，断言 `state == "skipped"` 就会假失败。改用「明天」。

## 六、已知缺口（下一步要补的）

1. **提前提醒的界面还没做**：`remind_offsets` 目前只能从库里/接口设（截图里「提前 5 分钟」的标签是演示数据带的）。
   下一步就在同一个编辑器里加一个「提前 N 分钟」下拉。
2. 工作日 = 周一至周五，**不看中国法定节假日**（要做得引节假日表，先不做）。
3. ~~每月 31 日只有 31 天的月份才响（2 月不响）~~ **已修**：现在做月末对齐（31 号在 2 月落 28/29、4 月落 30）。
4. ~~「工作日」= 周一至周五，不认法定节假日~~ **已修**：现在走 `holiday.rs`（2026 年国务院安排，含调休补班）。
4. 没有「跳过某一次」的独立入口（跳过 = 停止重复，或直接删掉那天的实例）。
5. 重复任务改期 = 改起始日（会按新起点重排实例），界面没有拖拽改期。
6. 前端按钮仍无自动化用例（靠截图 + 手工核对），只有 Rust 侧 106 个单测。
